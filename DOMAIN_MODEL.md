# DOMAIN_MODEL

## Назначение

Этот документ определяет основные сущности предметной области (Domain) проекта Arcaneum.

Все остальные подсистемы обязаны использовать именно эти сущности. Если появляется новая концепция, сначала она описывается здесь, а затем используется в коде.

---

# Главная идея

В Arcaneum пользователь работает не с моделями, а с **сессиями взаимодействия**.

Модель — лишь исполнитель.

Поэтому центральной сущностью проекта является не AI Provider и не Chat, а **Workspace**.

---

# Workspace

Workspace — рабочее пространство пользователя.

Оно объединяет:

- персонажей;
- чаты;
- память;
- Lorebook;
- настройки;
- активные модели;
- пользовательские инструкции;
- изображения;
- голосовые настройки.

Workspace должен экспортироваться и импортироваться как единое целое.

---

# User Profile

Хранит:

- имя пользователя;
- персональные инструкции;
- предпочтения;
- постоянную память пользователя;
- настройки интерфейса;
- языковые настройки.

---

# Character

Описывает исключительно персонажа.

Не содержит информации о модели.

Не содержит информации о провайдере.

Не содержит настроек API.

Содержит:

- личность;
- описание;
- пример речи;
- сценарий;
- аватар;
- приветствие;
- теги;
- дополнительные поля.

---

# Conversation

Представляет одну переписку.

Содержит:

- участников;
- сообщения;
- локальную память;
- активные правила;
- ссылки на изображения;
- ссылки на генерации.

---

# Message

Минимальная единица общения.

Сообщение должно быть неизменяемым после создания.

Редактирование создаёт новую ревизию.

---

# Prompt Context

Представляет полностью сформированный контекст, который отправляется модели.

Содержит ссылки на:

- Character;
- Memory;
- Lorebook;
- Summary;
- Author Notes;
- User Prompt.

---

# AI Provider

Предоставляет модели.

Не знает:

- что такое персонаж;
- что такое память;
- что такое чат.

Он получает только Prompt Context.

---

# Generation Job

Любая генерация (текст, изображение, голос) рассматривается как отдельная задача.

Это позволяет:

- показывать очередь;
- повторять запрос;
- отменять его;
- отслеживать статус;
- переключать провайдера.

---

# Asset

Любой внешний файл.

Например:

- изображение;
- аватар;
- голос;
- документ;
- резервная копия.

Все подсистемы работают через Asset Manager.

---

# Plugin

Любое расширение системы.

Плагин может добавлять:

- провайдера;
- тему;
- экспорт;
- импорт;
- инструменты;
- редакторы;
- новые типы генерации.

Плагины не должны изменять ядро приложения.

---

# Основной принцип Domain

Domain Layer не знает о существовании:

- React;
- IndexedDB;
- AI Horde;
- браузера;
- HTTP;
- JSON.

Он знает только бизнес-сущности.
