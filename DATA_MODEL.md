# DATA_MODEL

## Назначение

Data Model определяет каноническую структуру данных Arcaneum.

Все подсистемы обязаны использовать единые модели данных.

Запрещается создавать собственные несовместимые структуры без веской причины.

---

# Главный принцип

Каждая сущность имеет:

- уникальный идентификатор;
- метаданные;
- пользовательские данные;
- системные данные;
- историю изменений.

Это правило распространяется на все объекты проекта.

---

# Общая структура

Каждый объект должен содержать:

```text
id
type
version
createdAt
updatedAt
metadata
payload
extensions
```

---

## id

Глобально уникальный идентификатор.

Не изменяется никогда.

---

## version

Версия структуры объекта.

Используется для миграций.

---

## metadata

Хранит служебную информацию.

Например:

- автор;
- источник импорта;
- дата создания;
- дата изменения;
- используемые расширения.

---

## payload

Основные пользовательские данные.

Каждая подсистема самостоятельно определяет содержимое payload.

---

## extensions

Место подключения плагинов.

Ядро не должно знать содержимое extensions.

---

# Правило сериализации

Любой объект Arcaneum должен сериализоваться без потери данных.

Это обеспечивает:

- резервное копирование;
- перенос Workspace;
- экспорт;
- импорт;
- синхронизацию.

---

# Immutable First

После создания объекта его идентификатор и происхождение не изменяются.

Изменяется только payload.

Это упрощает аудит и историю изменений.
