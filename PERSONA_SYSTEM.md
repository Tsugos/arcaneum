# PERSONA_SYSTEM

## Назначение

Persona System является одной из центральных подсистем Arcaneum.

Она отвечает за описание любых интеллектуальных сущностей, участвующих в сессиях взаимодействия.

Система не ограничивается исключительно персонажами.

Она должна позволять описывать любые роли, необходимые для работы пользователя.

---

# Почему Persona, а не Character

Большинство существующих RP-клиентов рассматривают персонажа как единственную сущность.

Это ограничивает архитектуру.

Arcaneum использует более общий термин — Persona.

Персонаж является лишь одной из разновидностей Persona.

Это позволяет использовать единую систему для различных сценариев взаимодействия.

---

# Поддерживаемые типы Persona

На первом этапе архитектура должна предусматривать следующие типы:

- Character — обычный персонаж.
- Narrator — рассказчик.
- Assistant — помощник.
- Dungeon Master — ведущий настольной игры.
- World — описание мира.
- Companion — постоянный спутник.
- Custom — пользовательский тип.

Добавление новых типов не должно требовать изменения существующего кода.

---

# Состав Persona

Каждая Persona содержит:

- уникальный идентификатор;
- название;
- краткое описание;
- полное описание;
- приветственное сообщение;
- стиль речи;
- примеры диалогов;
- сценарий;
- аватар;
- дополнительные изображения;
- теги;
- пользовательские метаданные;
- версию.

---

# Независимость

Persona не знает:

- какая модель будет использоваться;
- какой AI Provider подключен;
- какие параметры генерации выбраны;
- какой Prompt Pipeline используется.

Persona описывает только личность и связанные с ней данные.

---

# Версионирование

Любое изменение Persona создаёт новую ревизию.

Это позволяет:

- отменять изменения;
- сравнивать версии;
- экспериментировать без потери предыдущего варианта.

---

# Импорт и экспорт

Система должна поддерживать импорт популярных форматов карточек персонажей через адаптеры.

При этом внутренним каноническим форматом Arcaneum остается собственная структура данных.

Внешние форматы не должны диктовать внутреннюю архитектуру.

---

# Расширяемость

Дополнительные поля Persona добавляются через систему расширений и не требуют изменения базовой модели.

Ядро должно уметь безопасно игнорировать неизвестные расширения.
