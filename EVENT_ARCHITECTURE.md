# EVENT_ARCHITECTURE

## Почему события

Arcaneum — это система, в которой множество независимых модулей должны взаимодействовать, не зная друг о друге напрямую.

Для этого используется событийная архитектура.

---

# Пример

Пользователь отправил сообщение.

Chat Engine публикует событие:

MessageCreated

Memory Engine получает событие и обновляет память.

Prompt Engine получает событие и пересчитывает контекст.

Notification Manager обновляет интерфейс.

Storage Manager сохраняет изменения.

Ни один из этих модулей не вызывает другой напрямую.

---

# Основные правила

События являются неизменяемыми.

Событие описывает факт, который уже произошел.

---

# Примеры событий

---

# Преимущества

Добавление новой системы не требует изменения существующих модулей.

Новая подсистема просто подписывается на необходимые события.

---

# Ограничения

События не должны использоваться как замена обычным вызовам функций.

Если модуль может напрямую использовать свой внутренний сервис без нарушения архитектуры — предпочтителен обычный вызов.

События предназначены для взаимодействия независимых подсистем, а не для любой коммуникации в приложении.
