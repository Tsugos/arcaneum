# ARCHITECTURE

## Назначение

Этот документ описывает общую архитектуру Arcaneum.

Архитектура является основой проекта и определяет взаимодействие всех подсистем.

---

# Главная идея

Arcaneum строится вокруг ядра приложения.

Ядро не знает:

- какой AI используется;
- где хранится память;
- каким образом устроены персонажи;
- какой интерфейс отображает данные.

Ядро знает только публичные контракты модулей.

---

# Высокоуровневая схема

```
                   UI Layer
                       │
                Application Layer
                       │
                  Domain Layer
                       │
                Service Layer
                       │
            Infrastructure Layer
```

Каждый слой имеет строго определенную ответственность.

---

## UI Layer

Отвечает только за отображение данных и взаимодействие с пользователем.

Не содержит бизнес-логики.

---

## Application Layer

Оркестрирует сценарии использования (Use Cases).

Не знает деталей реализации инфраструктуры.

---

## Domain Layer

Содержит основные сущности проекта и бизнес-правила.

Этот слой является самым важным и не должен зависеть ни от React, ни от AI Horde, ни от IndexedDB.

---

## Service Layer

Предоставляет сервисы, реализующие интерфейсы, определенные в Domain Layer.

Здесь располагаются менеджеры памяти, промптов, персонажей, моделей и других подсистем.

---

## Infrastructure Layer

Реализует работу с внешними API, файловой системой, IndexedDB, сетью и другими источниками данных.

Это единственный слой, который знает о конкретных технологиях.

---

# Главное правило

Зависимости направлены только сверху вниз по абстракциям.

Нижние уровни не должны определять поведение верхних.

Архитектура должна позволять заменить любую инфраструктурную реализацию без изменения бизнес-логики.
