# Философия Arcaneum

Arcaneum создается вокруг простой идеи:

**Пользователь должен владеть своим AI, а не сервис, через который он взаимодействует с ним.**

Современные AI-платформы часто ограничивают пользователя: привязывают его к одному провайдеру, одному интерфейсу, одному формату персонажей или навязывают определенный способ работы.

Arcaneum строится на противоположном принципе.

Каждая система должна быть независимой.

Любой модуль может быть заменен.

Любой AI-провайдер может быть подключен.

Любой формат данных может быть импортирован.

Пользователь должен самостоятельно определять, как именно будет работать его AI-клиент.

---

# Основные ценности

## Контроль

Все пользовательские данные принадлежат пользователю.

## Независимость

Ни одна подсистема не должна быть критически зависима от стороннего сервиса.

## Модульность

Каждый компонент должен иметь четкие границы ответственности.

## Масштабируемость

Любая новая функция должна интегрироваться без переписывания существующего кода.

## Прозрачность

Все процессы должны быть понятны пользователю.

По возможности система должна объяснять свои действия, а не скрывать их.

---

# Главный архитектурный принцип

Любая функция Arcaneum должна отвечать на вопрос:

> Можно ли заменить этот компонент, не переписывая остальную систему?

Если ответ отрицательный — архитектура требует пересмотра.

---

# Принцип развития

Arcaneum никогда не должен становиться "монолитом".

По мере роста проекта новые возможности добавляются через независимые подсистемы и расширения, а не путем усложнения существующих модулей.

---

# Роль документации

Документация является частью архитектуры.

Каждое значимое архитектурное решение должно быть отражено в документации до его реализации.

Код не должен становиться единственным источником знаний о проекте.
