# SESSION_SYSTEM

## Назначение

Session представляет собой основной пользовательский сценарий работы в Arcaneum.

В отличие от традиционного понятия "чат", Session описывает любое длительное взаимодействие пользователя с одной или несколькими Persona.

---

# Почему Session

Термин "чат" слишком ограничен.

Он предполагает лишь обмен сообщениями.

Однако Arcaneum должен поддерживать:

- обычные переписки;
- групповые диалоги;
- приключения;
- кампании;
- интерактивные истории;
- ролевые игры;
- смешанные сценарии.

Все они являются разновидностями Session.

---

# Структура Session

Session включает:

- участников;
- историю сообщений;
- локальную память;
- связанные Lorebook;
- настройки генерации;
- активные правила;
- пользовательские заметки;
- вложения;
- изображения;
- историю изменений.

---

# Независимость

Session не знает:

- каким AI Provider пользуется пользователь;
- как реализована память;
- каким образом собирается Prompt.

Она только хранит состояние взаимодействия.

---

# Типы Session

Архитектура должна поддерживать:

- One-to-One;
- Group;
- Adventure;
- Story;
- Sandbox;
- Custom.

---

# Жизненный цикл

Каждая Session проходит этапы:

Создание

↓

Настройка

↓

Активное взаимодействие

↓

Архивация

↓

Восстановление

Удаление допускается только по явному действию пользователя.

---

# История

История сообщений никогда не изменяется напрямую.

Любое редактирование фиксируется как отдельная ревизия.

Это обеспечивает воспроизводимость и возможность восстановления.
