# AI_ORCHESTRATOR

## Назначение

AI Orchestrator координирует взаимодействие всех подсистем перед обращением к языковой модели.

Он является единственной точкой входа для любых запросов к ИИ.

---

# Жизненный цикл запроса

1. Пользователь отправляет сообщение.
2. Story Engine обновляет историю.
3. Memory Engine выбирает релевантные воспоминания.
4. World State определяет актуальное состояние мира.
5. Lorebook Engine подбирает знания.
6. Rule Engine активирует необходимые правила.
7. Context Budget Engine распределяет токены.
8. Prompt Pipeline формирует универсальный контекст.
9. Provider Adapter адаптирует его под выбранную модель.
10. AI Provider выполняет генерацию.
11. Ответ проходит постобработку.
12. Session обновляется.

---

# Главный принцип

Все подсистемы работают независимо.

AI Orchestrator лишь определяет порядок их взаимодействия.

Он не содержит бизнес-логики отдельных модулей.

---

# Расширяемость

Добавление новой подсистемы не должно требовать переписывания существующего жизненного цикла.

Оркестратор должен позволять подключать новые этапы через конфигурацию или систему расширений.
