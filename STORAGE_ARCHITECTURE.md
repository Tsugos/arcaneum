# STORAGE_ARCHITECTURE

## Назначение

Storage Architecture определяет принципы хранения всех данных Arcaneum.

Подсистемы не должны знать, где физически находятся данные.

Они работают только через Storage API.

---

# Главный принцип

Хранилище является деталью реализации.

Замена IndexedDB на другую технологию не должна требовать изменений в Domain Layer.

---

# Storage Layer

Storage Layer отвечает за:

- сохранение;
- загрузку;
- удаление;
- индексацию;
- миграции;
- резервное копирование.

---

# Repository Pattern

Каждая крупная сущность имеет собственный Repository.

Например:

- PersonaRepository
- SessionRepository
- MemoryRepository
- StoryRepository
- AssetRepository

Repository не содержит бизнес-логики.

Он только предоставляет доступ к данным.

---

# Транзакции

Операции, изменяющие несколько связанных сущностей, должны выполняться атомарно.

Если одна часть операции завершается ошибкой, изменения не должны оставаться в частично применённом состоянии.

---

# Версионирование схем

При изменении структуры данных приложение автоматически запускает миграции.

Миграции должны быть обратимыми, когда это возможно.

---

# Offline First

Arcaneum проектируется как локальное приложение.

Все основные функции обязаны работать без постоянного подключения к интернету.

Интернет требуется только для обращения к внешним AI Provider.
